## Original Request

## User Preferences (from questions)

- **Edit style**: Replace Problem Description and Examples sections with full official text, examples, explanations and constraints. Keep Approach, Walkthrough etc. untouched.
- **Priority**: All files, alphabetical order.
- **Parallelism**: Yes, use subagents.
- **Custom files**: Enrich from context (add constraints and examples derived from the file's approach, clearly marked as not official).

## Strategy

1. **Source of truth**: LeetCode GraphQL API (`https://leetcode.com/graphql?query=query{question(titleSlug:"SLUG"){content}}`) for official problem text.
2. **Fallback**: doocs/leetcode GitHub repo for premium problems.
3. **Fallback**: Write from own knowledge if both fail.
4. **Parallel processing**: Split files into 21 alphabetical groups and launch background subagents.
5. **Non-official files**: Enrich from context with derived constraints/examples and add note: `> *Note: constraints and examples are derived, not from an official LeetCode source.*`
6. **Manual-check rule (applies to every session)**: If the official statement/examples/constraints of a problem cannot be confidently reproduced (very recent problem IDs, premium problems without a source, or custom files), **do not invent "official" text**. Either leave the file unedited or add a clearly marked derived/reconstructed note, and **add the file to the "Files Needing Manual Check" table** with its ID, the reason, and its status (❌ Not enriched / ⚠️ Unverified / ℹ️ Derived note added / ⏳ Pending). Update the table's status when a file is later verified.

## Verification Scripts

Saved in `scripts/` (next to this file; Python 3.6+, standard library only). Paths come from `scripts/lc_paths.py`: problem files = parent folder, fetch cache = `/tmp/lc` (env `LC_CACHE`), backups = `/tmp/bak` (env `LC_BAK`). Run from anywhere, e.g. `python3 scripts/verify.py "L*.md"`; glob arguments are relative to the problem folder.

| Script | Purpose |
|--------|---------|
| `lc_fetch.py SLUG` | Print official problem text as markdown (LeetCode GraphQL POST; doocs `README_EN.md` fallback for premium). Folder names in doocs drop punctuation (e.g. `:`); since session 5 the fallback retries with a cleaned title (stripped, `:` removed). If it still 404s, list the folder via `https://api.github.com/repos/doocs/leetcode/contents/solution/XX00-XX99`. |
| `triage.py GLOB...` | List files with NO_CONSTRAINTS / NO_URL / HIDDEN (U+202F, NBSP) / JUNK (`<!--`, "Actually", "Wait") / NOTE (derived/reconstructed) / SQL flags. |
| `verify.py GLOB...` | Fetch (cached) official text and flag files where an official example Input/Output, constraint line, SQL table row, or >30% of statement sentences are missing (after normalizing whitespace, superscripts, markdown). Prints `DIFF`, `NOURL`, `FETCHFAIL`. |
| `apply_official.py [--note "text"] FILE...` | Replace the **Problem Description**, **Examples** and **Constraints** sections with official text; every other section is left byte-identical. Adds a premium note automatically; `--note` for custom notes. Requires a cached fetch (run `verify.py` first). |
| `apply_keep_notes.py FILE...` | Wrapper around `apply_official.py` that re-inserts the manual `>` note blocks of the old Problem Description (e.g. wrong-approach notes) right after the header, dropping the automatic premium note when manual notes exist. Added in session 8. |
| `check_preserved.py` | Compare every file in the backup dir with the current file and report any change outside Description/Examples/Constraints. |
| `add_url.py "File.md=slug" ...` | Insert the missing `**LeetCode:**` line after Difficulty/Acceptance (validate the slug with `lc_fetch.py` first). |
| `strip_comments.py FILE...` | Remove `<!-- ... -->` blocks inside Description/Examples sections only. |
| `junkloc.py GLOB...` | Show line number + section of every junk line (to see whether it is in an editable section). |
| `fetch_many.py FILE...` | Pre-fetch official texts for a list of files into the cache. |
| `replace_section.py FILE START END NEWFILE` | Low-level: replace lines from the first line starting with START up to END. **Never use a generic prefix like `---`** (it caused the Friday Purchases I incident). Prefer `apply_official.py`. |

**Workflow per group:** `triage.py` → add URLs (`lc_fetch.py` to validate, then `add_url.py`) → `verify.py` → copy flagged files to the backup dir (empty it first) → `apply_official.py` → `check_preserved.py` (must report `bad 0`) → re-run `verify.py` (expect no `DIFF`) → skim old descriptions in the backup dir for files that described a *different* problem and add a `> *Note: …*` about the wrong Approach (edit manually). Custom/pattern files (no URL) need a manual derived note.
